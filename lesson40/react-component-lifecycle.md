# Жизненный цикл компонентов React

Жизненный цикл — это последовательность этапов, через которые проходит компонент: от первого появления на экране до удаления.

В React есть два подхода к компонентам. В современных проектах чаще используют **функциональные компоненты** и хуки, но классический жизненный цикл удобно понимать через **классовые компоненты**.

---

## Три основные фазы

| Фаза | Когда происходит | Простыми словами |
|------|------------------|------------------|
| **Монтирование (Mounting)** | Компонент впервые создаётся и попадает в DOM | Компонент «родился» и появился на странице |
| **Обновление (Updating)** | Меняются props, state или родитель перерисовывается | Компонент «обновился» из-за новых данных |
| **Размонтирование (Unmounting)** | Компонент удаляется со страницы | Компонент «умер» и исчез из DOM |

---

## 1. Монтирование (Mounting)

Компонент только что создан. React строит UI и вставляет его в страницу.

### Этапы по порядку

1. **constructor** — конструктор класса. Инициализация state, привязка методов. Вызывается один раз.
2. **render** — React вычисляет, что нужно показать (возвращает JSX).
3. **React обновляет DOM** — результат `render` попадает на страницу.
4. **componentDidMount** — компонент уже на экране. Подходит для запросов к API, подписок, таймеров.

### Пример (классовый компонент)

```jsx
class UserCard extends React.Component {
  constructor(props) {
    super(props);
    this.state = { user: null };
  }

  componentDidMount() {
    // компонент уже в DOM — можно работать с сетью
    fetch('/api/user')
      .then((res) => res.json())
      .then((user) => this.setState({ user }));
  }

  render() {
    return <div>{this.state.user?.name ?? 'Загрузка...'}</div>;
  }
}
```

### Аналог в функциональном компоненте

```jsx
function UserCard() {
  const [user, setUser] = useState(null);

  useEffect(() => {
    // аналог componentDidMount
    fetch('/api/user')
      .then((res) => res.json())
      .then(setUser);
  }, []); // пустой массив зависимостей = выполнить один раз после монтирования

  return <div>{user?.name ?? 'Загрузка...'}</div>;
}
```

## 2. Обновление (Updating)

Компонент уже существует, но что-то изменилось: новые props, новый state, перерисовка родителя.

### Этапы по порядку

1. **render** — React заново вычисляет JSX с учётом новых данных.
2. **React обновляет DOM** — меняются только те части страницы, которые действительно изменились.
3. **componentDidUpdate** — компонент уже обновлён на экране. Можно реагировать на изменение props или state.

> **componentDidUpdate(prevProps, prevState)** — в аргументах лежат предыдущие значения. Так можно сравнить «было» и «стало».

### Пример (классовый компонент)

```jsx
componentDidUpdate(prevProps) {
  if (prevProps.userId !== this.props.userId) {
    // userId изменился — загружаем нового пользователя
    this.loadUser(this.props.userId);
  }
}
```

### Аналог в функциональном компоненте

```jsx
useEffect(() => {
  // сработает после каждого изменения userId
  loadUser(userId);
}, [userId]);
```

### Дополнительные методы обновления (классовые компоненты)

| Метод | Назначение |
|-------|------------|
| **shouldComponentUpdate** | Можно запретить лишнюю перерисовку, если данные не изменились |
| **getSnapshotBeforeUpdate** | Редко используется. Сохраняет «снимок» DOM перед обновлением (например, позицию скролла) |
| **componentDidUpdate** | Действия после обновления DOM |

В функциональных компонентах роль `shouldComponentUpdate` часто выполняют **`React.memo`**, **`useMemo`** и **`useCallback`**.

## 3. Размонтирование (Unmounting)

Компонент больше не нужен: пользователь ушёл со страницы, элемент скрыли условием `{isVisible && <Modal />}`, список сократился.

### Этап

1. **componentWillUnmount** — последний шанс убрать «хвосты»: отписаться от событий, остановить таймер, отменить запрос.

### Пример (классовый компонент)

```jsx
componentDidMount() {
  this.timerId = setInterval(() => this.tick(), 1000);
}

componentWillUnmount() {
  clearInterval(this.timerId);
}
```

### Аналог в функциональном компоненте

```jsx
useEffect(() => {
  const timerId = setInterval(() => tick(), 1000);

  return () => {
    // функция очистки — аналог componentWillUnmount
    clearInterval(timerId);
  };
}, []);
```

Если не очистить подписки и таймеры, возможны утечки памяти и ошибки «обновление удалённого компонента».

---

## Сводная схема

```
МОНТИРОВАНИЕ
constructor → render → DOM → componentDidMount
                              ↓
ОБНОВЛЕНИЕ (может повторяться много раз)
render → DOM → componentDidUpdate
                              ↓
РАЗМОНТИРОВАНИЕ
componentWillUnmount
```

## Функциональные компоненты: как это выглядит с хуками

| Фаза жизненного цикла | Классовый метод | Хук / приём |
|-----------------------|-----------------|-------------|
| После монтирования | `componentDidMount` | `useEffect(() => { ... }, [])` |
| После обновления | `componentDidUpdate` | `useEffect(() => { ... }, [dep1, dep2])` |
| Перед размонтированием | `componentWillUnmount` | `return () => { ... }` внутри `useEffect` |
| Синхронно после render, до paint | — | `useLayoutEffect` |

### `useEffect` — главный хук для побочных эффектов

```jsx
useEffect(() => {
  // 1. код эффекта (после render)
  console.log('эффект выполнился');

  return () => {
    // 2. очистка (перед следующим эффектом или при размонтировании)
    console.log('очистка');
  };
}, [count]); // 3. зависимости — когда перезапускать эффект
```

**Как читать массив зависимостей:**

- `[]` — один раз после монтирования (как `componentDidMount`)
- `[a, b]` — при изменении `a` или `b` (как `componentDidUpdate` для этих значений)
- без массива — после каждого render (используют редко)

## Устаревшие методы (знать для чтения старого кода)

В старых версиях React были методы с префиксом `UNSAFE_`:

- `UNSAFE_componentWillMount`
- `UNSAFE_componentWillReceiveProps`
- `UNSAFE_componentWillUpdate`

Их не используют в новом коде. Вместо них — `componentDidMount`, `componentDidUpdate`, `getDerivedStateFromProps` или хуки.

---

## Краткая шпаргалка

1. **Mount** — компонент появился → загрузка данных, подписки.
2. **Update** — данные изменились → синхронизация с API, пересчёт.
3. **Unmount** — компонент исчез → очистка таймеров, отписок, запросов.

Главное правило: всё, что вы «подключили» в `componentDidMount` или в `useEffect`, нужно «отключить» в `componentWillUnmount` или в функции очистки `useEffect`.
