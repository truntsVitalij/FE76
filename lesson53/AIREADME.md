# Работа с AI в разработке: инструменты, модели, правила, паттерны

Материал для занятия: как **учиться** с AI и **использовать** его в коде без иллюзий и рисков.

> **Одной фразой:** AI — это **ассистент**, не замена мозга: вы формулируете задачу, проверяете ответ, запускаете код и несёте ответственность за результат. Хороший промпт = контекст + цель + ограничения + формат ответа.

## Зачем AI разработчику

| Задача | Как AI помогает |
|--------|-----------------|
| Объяснить код / ошибку | Разбор stack trace, HTTP 403, «почему useEffect дважды» |
| Набросать boilerplate | Компонент, тест, конфиг Vite |
| Рефакторинг | Переименовать, вынести хук, упростить |
| Документация | README, комментарии к API |
| Поиск идеи | «Как сделать PKCE без backend» → направление, не gospel |
| Учёба | Объяснить REST, JWT, RTL «как для занятия» |
| Тесты | unit-tests

AI **не заменяет**: понимание основ, code review, тесты, продакшен-ответственность.

## Как изучать работу с AI

### Принцип: учиться **вместе** с AI, а не **вместо** себя

```
1. Сначала попробуй сам (15–30 мин)
2. Застрял → спроси AI с контекстом
3. Получил ответ → прочитай, не копируй вслепую
4. Запусти / проверь / измени
5. Сформулируй, *почему* сработало
```

### План на 2–4 недели (для курса)

| Неделя | Фокус | Практика |
|--------|--------|----------|
| 1 | Термины, один чат (ChatGPT / Claude) | Объяснения: HTTP, React hooks, ошибки |
| 2 | IDE-ассистент (Cursor / Copilot) | Мелкие правки в `diplom`, не «сделай всё» |
| 3 | Структурные промпты | Задача + файлы + ограничения + «не трогай X» |
| 4 | Критика ответов AI | Сравнить 2 ответа, найти галлюцинацию, написать тест |

### Как понять, что вы **научились**, а не только AI

- Можете объяснить решение без подсказок.
- Можете воспроизвести код с нуля на доске / в новом файле.
- Замечаете, когда AI врёт (устаревший API, несуществующий метод).
- Умеете сузить промпт и получить полезный diff, а не простыню.

## Как работает LLM

### Упрощённая схема

```
Текст из интернета / книг / кода (обучение)
              ↓
    Нейросеть учится: «какое слово (token) вероятно следующее?»
              ↓
    Готовая модель (GPT, Claude, Qwen, DeepSeek…)
              ↓
    Вы шлёте prompt → модель по одному token генерирует ответ
```

LLM **не ищет** ответ в базе данных как Google. Она **предсказывает** продолжение текста, опираясь на паттерны из обучения и ваш контекст.

### Этапы жизни модели

| Этап | Что происходит |
|------|----------------|
| **Pre-training** | Модель «читает» огромные тексты и учится предсказывать следующий token |
| **Fine-tuning / alignment** | Донастройка: следовать инструкциям, быть полезнее, отказывать в опасном |
| **Inference** | Вы пишете промпт → модель генерирует ответ token за token |

### Token — единица текста

- Текст режется на **tokens** (куски слов, символов).
- Лимит **context window** — сколько tokens помещается в один запрос (промпт + ответ + история).
- Цена API и скорость часто считаются в tokens.

Пример (условно): `"React"` может быть 1 token, `"import"` — 1 token, длинный файл — тысячи.

### Transformer (без математики)

Современные LLM построены на архитектуре **Transformer**:

- Смотрит на **все** слова промпта сразу (attention) — понимает связи «кнопка ↔ onClick ↔ form».
- На выходе — вероятность следующего token.
- Так строится и код, и prose.

### Что модель **не** делает

| Миф | Реальность |
|-----|------------|
| «Думает как человек» | Статистика + огромный объём примеров |
| «Знает ваш проект» | Видит только то, что вы **передали** в контекст | ??
| «Всегда актуальна» | Knowledge cutoff + галлюцинации | ??
| «Выполняет код» | Пишет текст; запуск — у вас или у Agent с терминалом | ??
| «Помнит прошлый чат вечно» | Ограниченное окно; длинные треды «забываются» | ??

### Почему бывают галлюцинации

- Модель оптимизирована на **правдоподобный** текст, не на «я не знаю».
- Редкий API → модель «достроит» похожий, но несуществующий метод.
- Нет доступа к вашему `node_modules` → может предложить старую версию пакета.

**Вывод для разработчика:** LLM — мощный **автодополнитель текста/кода**, не оракул. Проверка — ваш job.

### Inference vs Agent

| Режим | Смысл |
|-------|--------|
| **Chat / completion** | Один запрос → текст (код в ответе) |
| **Agent (Cursor и др.)** | Модель + инструменты: читать файлы, править, запускать команды |
| **RAG** | Перед ответом подмешивают куски **ваших** доков (docs, wiki) |

## Инструменты

### Категории

| Категор | Примеры | Для чего |
|---------|---------|----------|
| **Чат-ассистенты** | ChatGPT, Claude, Gemini, Grok | Вопросы, объяснения, черновики кода |
| **IDE / редактор** | **Cursor**, GitHub Copilot, JetBrains AI | Код в контексте проекта, Agent, inline |
| **Встроенные в продукт** | Notion AI, Figma AI | Тексты, макеты — не основной dev-стек |
| **API для приложений** | OpenAI API, Anthropic API, OpenRouter | Свой бэкенд с LLM |
| **Локальные модели** | Ollama, LM Studio | Приватность, офлайн, слабее облака |
| **Специализированные** | v0 (UI), Phind, Perplexity | UI-прототипы, поиск с источниками |

### Cursor (ваш контекст курса)

| Возможность | Смысл |
|-------------|--------|
| Chat | Диалог с контекстом открытых файлов |
| Agent / Composer | Многошаговые правки по репозиторию |
| Tab completion | Дополнение строк как Copilot |
| Rules / Skills | Постоянные инструкции для проекта |
| @-mentions | `@file`, `@folder`, `@docs` — явный контекст |

### GitHub Copilot

- Inline-подсказки в VS Code / JetBrains.
- Copilot Chat — отдельный чат в IDE.
- Хорош для **мелких** дополнений; большие фичи — лучше явный промпт + review.

### ChatGPT / Claude (веб или приложение)

- Универсальные чаты, сильны в объяснениях и черновиках.
- Минус: **нет** автоматического доступа ко всему вашему репо (нужно вставлять код / файлы).

### Perplexity / поиск с AI

- Ответы со **ссылками** — удобно для «актуальная версия Vite / Spotify API».
- Всё равно перепроверяйте официальную доку.

### Сравнение «что когда»

| Ситуация | Инструмент |
|----------|------------|
| «Объясни 403 на /v1/me» | Чат |
| «Поправь alias в vite.config» | Cursor Agent + открытый файл |
| «Допиши `expect(...)` в тесте» | Copilot / Tab |
| «Сгенерируй README урока» | Чат + ваш outline |
| «Секреты / prod DB» | **Никакой** публичный AI |

## ChatGPT, DeepSeek, Qwen-turbo, Copilot

Четыре популярных варианта **ассистента разработчика** — сравнение на уровне курса (детали тарифов и моделей меняются).

| | **ChatGPT** | **DeepSeek** | **Qwen-turbo** | **GitHub Copilot** |
|--|-------------|--------------|----------------|---------------------|
| **Где** | Web / app / API (OpenAI) | Web / app / API | Web / API (Alibaba) | VS Code, JetBrains, GitHub |
| **Сильнее всего** | Универсальность, экосystem, reasoning-модели | Код, цена API, сильные open-weight модели | Быстрые ответы, мультиязычность (в т.ч. CN) | Inline в IDE, привычный flow |
| **Слабее** | Нет доступа к репо без вставки | Меньше «обвязки» IDE из коробки | Turbo = быстрее, но проще на сложном | Слабее на больших рефакторингах без Agent |
| **Контекст проекта** | Вручную (файлы, paste) | Вручную | Вручную | Открытый файл + соседний код |
| **Для учёбы** | Объяснения, README, алгоритмы | Дешёвый код-чат | Быстрые черновики | Дописать строку, тест, prop types |
| **Приватность** | Политика OpenAI | Политика DeepSeek | Политика Alibaba | Политика GitHub/Microsoft |

### ChatGPT (OpenAI)

- **Когда:** объяснить концепцию, разобрать ошибку, набросать архитектуру, написать доку.
- **Как dev-ассистент:** вставляете stack trace, куски кода, скрин Network tab.
- **Совет:** для актуальных API (Spotify, Vite 8) уточняйте версию в промпте или сверяйтесь с докой.

### DeepSeek

- **Когда:** много кодогенерации, эксперiments, API с упором на цену.
- **Сильные open / chat модели** — часто используют как альтернативу GPT в чатах и через API.
- **Совет:** как и везде — не доверять импортам и версиям пакетов без `npm install` / доки.

### Qwen-turbo (Alibaba Qwen)

- **Turbo** — облегчённая / быстрая линейка: хороша для **коротких** задач (объясни hook, допиши CSS, переведи коммент).
- На **сложный** рефакторинг лучше более тяжёлые модели той же семьи (Qwen-Plus / Max — названия у провайдera).
- **Когда:** быстрые итерации на русском/английском, прототипы текста и кода.

### GitHub Copilot

- **Inline:** серые подсказки — Tab принять.
- **Chat:** вопросы по выделенному коду.
- **Copilot Workspace / Agent** (если доступно) — ближе к Cursor по сценарию «задача → правки».
- **Когда:** ежедневное дописывание в **привычной IDE** без смены редактора.
- **Минус:** без явного промпта «не трогай X» может раздуть diff.

### Как комбинировать

```
Объяснение / теория     → ChatGPT / DeepSeek / Qwen (чат)
Строка кода / тест      → Copilot Tab
Фича в репозитории      → Cursor / Windsurf Agent
Актуальная дока         → Perplexity + официальный сайт
```

## Современные AI IDE: Cursor, Windsurf, Lovable

**AI IDE** — редактор, где LLM встроен в workflow: контекст проекта, multi-file edit, терминал, иногда preview.

### Сравнение

| | **Cursor** | **Windsurf** (Codeium) | **Lovable** |
|--|------------|------------------------|-------------|
| **База** | Fork VS Code | Fork VS Code | Web-платформа (full-stack прототипы) |
| **Фокус** | Agent, Composer, Rules, много моделей | Flows, Cascade agent, контекст repo | Быстрый MVP: UI + backend из промпта |
| **Ваш код** | Полный контроль локального репо | Полный контроль локального репо | Экспорт / интеграция, меньше «ручного» repo на старте |
| **Лучше для** | Диплом, production-fe, daily dev | Альтернатива Cursor, те же задачи | Landing, admin, CRUD-прототип за часы |
| **Слабее для** | Нужно учить промпты и review | Меньше community-материалов чем Cursor | Сложная кастомная архитектура, Spotify OAuth edge cases |

### Cursor AI

| Фича | Зачем |
|------|--------|
| **Chat** | Вопросы с `@file` / `@codebase` |
| **Agent / Composer** | Многофайловые задачи («добавь PKCE auth») |
| **Tab** | Autocomplete |
| **Rules / .cursorrules** | Стиль проекта: «CSS modules, alias @, без any» |
| **Выбор модели** | GPT, Claude, Gemini под задачу |

**Курс:** основной инструмент для `diplom` — правки в реальном дереве файлов.

### Windsurf

- Редактор от **Codeium** с акцентом на **Flows** / **Cascade** — agent держит контекст сессии и repo.
- Похожий с Cursor сценарий: описали задачу → правки в нескольких файлах → diff review.
- **Когда пробовать:** если уже пользуетесь Codeium или хотите второй AI IDE для сравнения.

### Lovable

- **Не классическая IDE**, а **генератор приложений**: промпт → React UI + часто Supabase/backend.
- Сильна для **быстрого прототипа**: лендинг, dashboard, форма, список.
- **Слабее** для точного повторения Spotify-like UX или глубокой интеграции с вашим monorepo.
- **Workflow:** набросали в Lovable → экспортировали → доработали в Cursor локально.

### Что выбрать студенту

| Цель | Инструмент |
|------|------------|
| Учиться и сдавать диплом с пониманием | **Cursor** (или Windsurf) + локальный git |
| Быстро показать макет заказчику | Lovable / v0 |
| Только дописывать строки | Copilot в VS Code |
| Теория на занятии | ChatGPT / DeepSeek / Qwen в браузере |

## Модели (обзор)

Модели меняются часто; смотрите актуальные списки у провайдера. Ниже — **классы**, не «лучшая навсегда».

### По провайдеру (примеры семейств)

| Провайдер | Модели (примеры) | Сильные стороны |
|-----------|------------------|----------------|
| **OpenAI** | GPT-4o, GPT-4.1, o-series (reasoning) | Код, инструменты, экосистема |
| **Anthropic** | Claude Sonnet, Opus | Длинный контекст, аккуратный код, текст |
| **Google** | Gemini Pro / Flash | Скорость, мультимodal |
| **DeepSeek** | DeepSeek-V3 / Coder | Код, API, open weights |
| **Alibaba** | Qwen-turbo, Qwen-Plus | Скорость / баланс / качество |
| **Meta (open)** | Llama | Локально / через хостинг |
| **Cursor** | Несколько моделей в одном UI | Выбор под задачу в IDE |

### По типу задачи

| Тип | Что выбрать |
|-----|-------------|
| Быстрый вопрос, черновик | «Flash» / быстрые модели |
| Сложный рефакторинг, архитектура | Сильные general / reasoning |
| Длинный контекст (много файлов) | Модели с большим context window |
| Приватность | Локальная Llama через Ollama |

### Параметры, о которых стоит знать

| Параметр | Смысл |
|----------|--------|
| **Context window** | Сколько текста «помнит» за раз (файлы + история) |
| **Temperature** | Выше → креативнее и разброснее; для кода часто ниже |
| **Multimodal** | Картинки, скрины UI, диаграммы |
| **Tools / function calling** | Модель вызывает поиск, терминал, API |

### Ограничения моделей

- **Knowledge cutoff** — не знают события после даты обучения.
- **Галлюцинации** — уверенно выдумывают API, пакеты, цитаты.
- **Недетерминизм** — один промпт → разные ответы.
- **Язык** — русский и английский обычно ок; для кода чаще пишут промпт на EN.

## Плюсы и минусы

### Плюсы

| + | Пояснение |
|---|-----------|
| Скорость старта | Boilerplate, конфиги, тесты-черновики |
| 24/7 «репетитор» | Объяснения без стыда «глупого вопроса» |
| Другой угол | Альтернативная структура, naming |
| Документация | Черновики README, комментарии |
| Рутина | Regex, миграции, форматирование |

### Минусы

| − | Пояснение |
|---|-----------|
| Галлюцинации | Несуществующие методы, устаревший синтаксис |
| Уверенный тон | Звучит правильно, даже когда нет |
| Плохой контекст | Без файлов/стека — generic-ответ |
| Зависимость | Перестаёте думать сами |
| Безопасность | Утечка секретов, лицензии, плагиат |
| Стоимость | Платные подписки и API |
| «Слишком много кода» | Over-engineering в одном промпте |

### Когда AI особенно полезен

- Застряли на ошибке с **полным** stack trace.
- Нужен **шаблон** (Vitest setup, Cypress config).
- Рефакторинг **локальный**, с тестами.

### Когда осторожнее

- Auth, crypto, payments, PII.
- «Сделай весь диплом за меня» без понимания.
- Production config без review.

## Базовые термины

| Термин | Одной строкой |
|--------|----------------|
| **LLM** (Large Language Model) | Большая языковая модель — предсказывает текст по контексту |
| **Prompt** | Ваш запрос + контекст |
| **Completion** | Ответ модели |
| **System prompt** | Скрытые инструкции «как вести себя» (роль, правила) |
| **Context / context window** | Всё, что модель «видит» в одном запросе |
| **Token** | Кусок текста (~слово/часть слова); от этого цена и лимит |
| **Hallucination** | Выдуманный факт или API |
| **RAG** | Retrieval-Augmented Generation — ответ + поиск по вашим документам |
| **Fine-tuning** | Дообучение модели на своих данных (редко нужно студенту) |
| **Agent** | AI с инструментами: файлы, терминал, браузер |
| **Inline completion** | Подсказка прямо в строке кода (Tab) |
| **Temperature** | «Случайность» ответа |
| **Multimodal** | Текст + картинки/аудио |
| **Reasoning model** | Модель с явным «рассуждением» (o-series и аналоги) |
| **Knowledge cutoff** | Дата, после которой модель не «знает» мир из обучения |

## Базовые правила

### 1. Вы владелец кода

- Всё, что попало в репозиторий — **ваша** ответственность на review и в проде.
- AI не подписывает коммиты за вас.

### 2. Контекст решает

Плохо:

```text
почему не работает fetch
```

Хорошо:

```text
React 19 + Vite, GET https://api.spotify.com/v1/me,
Authorization: Bearer <token>, статус 403, тело пустое.
redirect_uri и scope уже проверил. Код в sign-in.tsx строки 28–43.
```

### 3. Проверяйте факты

- Официальная дока > ответ AI.
- Запуск `npm test`, Network tab, `tsc` — обязательны.

### 4. Не сливайте секреты

- `client_secret`, JWT, `.env`, пароли, персональные данные — **не в чат**.
- Скриншоты — без токенов в DevTools.

### 5. Маленькие шаги

- Один промпт — одна задача (alias, один тест, один баг).
- Проще review и откат.

### 6. Просите формат ответа

- «Только diff», «список из 3 пунктов», «без воды», «сначала причина, потом fix».

### 7. Учитесь на ответе

- «Объясни, *почему* это работает» — второй промпт после fix.

### 8. Английский для кода

- Промпт можно на RU; имена переменных и технические термины — как в проекте (часто EN).

## Хороший и плохой промпт — разбор примеров

Ниже — типичные сценарии фронтенда. **Плохой** промпт → размытый или опасный ответ. **Хороший** → можно сразу применять и проверить.

### 1. Отладка fetch

**Плохо:**

```text
почему fetch не работает
```

*Проблема:* нет URL, статуса, стека, файла. AI выдаст generic про CORS.

**Хорошо:**

```text
React 19 + Vite, diplom/src/pages/home/home.tsx
GET https://api.spotify.com/v1/me
Headers: Authorization: Bearer <есть в LS>
Response: 403, body пустой
User уже в Spotify Dashboard allowlist.
Что проверить дальше? Список из 3 пунктов, без кода.
```

---

### 2. Новый компонент

**Плохо:**

```text
сделай сайдбар как у Spotify
```

*Проблема:* нет стека, папки, стилей. Получите 200 строк с Tailwind, хотя у вас CSS modules.

**Хорошо:**

```text
Добавь список плейлистов в UserLibrarySidebar (diplom).
Стек: React 19, CSS modules, lucide-react, fetch /v1/me/playlists + Bearer из useAccessToken.
Повтори структуру header из user-library-sidebar.tsx.
Пока только loading + список name, без роутинга.
Минимальный diff, не трогай sign-in.
```

---

### 3. Тесты

**Плохо:**

```text
напиши тесты
```

**Хорошо:**

```text
Vitest + RTL, файл button.test.tsx уже есть как образец.
Напиши тест для SignInForm:
- видна кнопка "Sign in" (getByRole)
- при клике вызывается redirectToSpotifyAuth (vi.mock)
Один describe, два it. Без snapshot.
```

### 4. Рефакторинг

**Плохо:**

```text
улучши код sign-in
```

**Хорошо:**

```text
В sign-in.tsx вынеси обмен code→token в api/spotify-auth.ts (PKCE уже там).
Поведение и redirect_uri не менять.
Покажи только diff двух файлов.
```

### 5. Обучение (без кода)

**Плохо:**

```text
объясни JWT
```

**Хорошо:**

```text
Объясни JWT для занятия lesson50:
header.payload.signature, что в payload можно/нельзя,
разница access vs refresh, 401 vs 403.
До 10 пунктов, простым языком, без воды.
```

**Плохо:**


### 7. Секреты (антипример)

**Плохо (опасно):**

```text

```

**Хорошо:**

```text

Секреты не привожу — подскажи checklist.
```

```text
☐ Одна задача на промпт
☐ Ограничения (не трогать X, без новых deps)
```

## Лучшие паттерны промптов

### Структура **CRTC** (удобная шпаргалка)

| Буква | Часть | Пример |
|-------|--------|--------|
| **C** Context | Стек, файлы, что уже пробовали | «Vite 8, React 19, diplom/sign-in.tsx» |
| **R** Role | Кто AI | «Ты senior frontend, кратко» |
| **T** Task | Что сделать | «Исправь alias @ без ломания imports» |
| **C** Constraints | Ограничения | «Не трогай spotify-auth.ts, минимальный diff» |

### Паттерн **RTF** (Role — Task — Format)

```text
Role: репетитор по React Testing Library.
Task: объясни разницу getBy / queryBy / findBy на примере SignIn.
Format: таблица + один короткий тест на Vitest.
```

### Паттерн **Chain-of-thought** (для сложного)

```text
Разбери по шагам:
1) что означает invalid_grant от Spotify
2) типичные причины в SPA
3) что проверить в моём коде (список)
Не пиши код, пока не перечислишь шаги.
```

### Паттерн **Critique** (самопроверка AI)

```text
Предложи fix для 403 на /v1/me.
Затем перечисли 3 способа, как твоё решение может быть неверным.
```

### Паттерн **Few-shot** (примеры)

```text
Вот рабочий тест Button (Vitest + RTL):
[вставить код]

Напиши такой же для SignInForm: кнопка Sign in видна.
```

### Паттерн **Negative prompt** (чего не делать)

```text
Не используй Enzyme.
Не добавляй новые зависимости.
Не рефактори unrelated файлы.
Не выдумывай API Spotify — только /v1/me и /v1/me/playlists.
```

### Итерация

```text
1-й промпт: набросок
2-й: «короче / только vite.config»
3-й: «добавь paths в tsconfig»
4-й: «почему path.resolve, а не "/src"?»
```

## Верстка, стилизация и прототипирование с AI IDE

AI сильнее всего ускоряет **повторяемую** верстку и **итерации** «почти как в макете», если вы держите рамки (CSS modules, дизайн-токены, существующие компоненты).

### Workflow ускорения

```
1. Референс (скрин Spotify / Figma / свой макет)
2. Промпт: структура + ограничения стека
3. Agent правит .tsx + .module.css
4. npm run dev → смотрите в браузере
5. Уточняющий промпт: «padding 12px», «иконка 16px», «hover как button»
6. Вы сами вычищаете лишнее и выравниваете a11y
```

### 1. Верстка по скриншоту

В Cursor / Windsurf:

```text
@user-library-sidebar.tsx
По приложенному скрину: левая колонка библиотеки.
Flex column, header с иконками, список карточек плейлистов.
CSS modules, цвета близко к Spotify dark theme.
Не меняй логику fetch — только layout и классы.
```

Прикрепите **скрин** (multimodal) — модель видит пропорции лучше, чем по слову «красиво».

### 2. Стилизация в существующем проекте

```text
Приведи sign-in.module.css к стилю main-layout (тёмный фон, центрированная карточка).
Переиспользуй переменные/цвета из reset.css если есть.
Не inline styles. Не Tailwind.
```

**Паттерн «как в файле X»** с `@`-mention снижает визуальный разнобой.

### 3. Компонент из описания

```text
Создай shared/loader: спиннер 24px, aria-label="Loading", CSS module.
Экспорт из index.ts. Без сторонних UI-kit.
```

Маленькие UI-кирпичи AI делает быстро — **review** на accessibility (`role="status"`).

### 4. Прототипирование

| Инструмент | Сценарий |
|------------|----------|
| **Lovable** | За вечер — кликабельный MVP с формой и таблицей |
| **Cursor Agent** | Новая страница в `diplom` с роутом и layout |
| **Storybook + AI** | Сгенерировать stories для состояний (empty, loading, error) |
| **v0 (Vercel)** | Черновик UI-компонента → скопировать разметку в проект |

Цепочка для курса:

```
Lovable/v0 (идея layout) → экспорт/копипаст → Cursor (вписать в diplom + CSS modules + API)
```

### 5. Итерации стилей (короткие промпты)

После первого результата — **узкие** правки:

```text
.sidebar item: gap 8px, border-radius 4px, hover background #282828
```

```text
Заголовок library: font-size 14px, font-weight 600, color rgba(255,255,255,0.7)
```

```text
На mobile < 768px sidebar скрыт (display none) — только media query в module.css
```

### 6. Что ускорять, что делать руками

| AI IDE быстро | Лучше руками + review |
|---------------|------------------------|
| Flex/grid каркас | Pixel-perfect бренд-гайд |
| Повтор hover/focus | Сложная анимация 60fps |
| Копипаст spacing | Доступность форм (label, focus trap) |
| Тёмная тема «в духе» | Юридически точные тексты |
| Skeleton / empty state | OAuth redirect edge cases |

### 7. Rules для верстки в Cursor

`.cursor/rules` или project rules:

```text
- CSS Modules only, no Tailwind
- Colors: dark bg #121212, elevated #181818
- Reuse shared/button and shared/text
- Icons: lucide-react size 14–16
- Mobile-first not required for diplom
```

Agent будет **стабильнее** попадать в ваш стиль.

### 8. Связь со Storybook

```text
@sign-in-form.stories.tsx @sign-in-form.tsx
Добавь story Loading с mock delay и story Error с текстом ошибки.
tags: autodocs
```

Storybook + AI = быстрые **состояния** UI без полного приложения.

## Чего не делать

| Антипаттерн | Почему плохо |
|-------------|--------------|
| «Сделай приложение целиком» | Непонятно, не поддерживаемо |
| Копировать код без чтения | Баги и секреты |
| Доверять версиям пакетов AI | Может предложить устаревшее |
| Спорить с ошибкой компилятора | TS/ESLint правы чаще |
| Просить «обойти» auth/CORS «хаком» | Опасно и не учит |
| Один чат на весь семестр | Контекст забивается, путаница |
| Сдавать AI-текст как своё без понимания | Провал на защите / собесе |

## Безопасность и этика

| Правило | Деталь |
|---------|--------|
| Секреты | Только env / CI, не в промпт |
| PII | Не загружать данные пользователей |
| Лицензии | Код из AI — проверять совместимость с проектом |
| Академическая честность | Уточняйте правила курса: что можно с AI |
| Bias | Модель может устаревшие стереотипы в текстах |
| Логи провайдера | Корпоративные данные — политика компании |
