### Как мы решаем merge-conflict'ы:

1. Пулим base ветку в compare ветку
2. Руками исправляем конфликты. Оставляем только те строки, которые действительно верны
3. Делаем git add для каждого файла с конфилктами (нажимаем на плюсик)
4. git rebase --continue
5. git включит VIM для того, чтобы вы написали мессейдж для мерж-коммита
6. Пишем мессейдж. Нажимаем ESC -> :wq
7. Если появились новые конфликты. Возвращаемся в пункт номер 2. И там по кругу пока все конфликты не закончатся
8. Делаем git push -f origin branch_name

### Если появились левые 10к изменения

перезагрузите IDE. ПРоверьте через git status. Добавить git-ignore

### Обсуждения во время занятия

1. props-drilling - проброс данных от родителя с дочерний элемент на n-уровень через пропсы и эти данные нужны ТОЛЬКО дочернему элементу. То есть на промежуточном уровне у нас пропс ради пропса
2. Store - хранилище данных
3. Action - запрос от пользователя.
4. REducer - обёртка, перехватывающая любой запрос от пользователя. Внутри этой обёртки описана логика работы с Stor'ом и правила его изменения
5. Диспетчер (Dispatch) - шаг, на котором человекоподобный запрос перерабатывается и пробрасывается в Reducer
6. Selector - способ подписки на любые изменения в store
